Work unit 1 — Login & session

Implement username/password login using the Login API contract in spec/apis_contract/ and spec/SPEC_FREEZE.md. UX: spec/ux/ux-design-of-login.png.

- Centered card on a light page; MyShop + bag-style mark; Welcome Back (or equivalent) and login instruction text.
- Labeled username field (placeholder and leading user icon as in the UX); labeled password field (lock icon, show/hide control, placeholder); primary full-width Login button.
- Loading state, empty-field validation, invalid-credential handling (DummyJSON HTTP 400 { "message": "Invalid credentials" }), and network-error handling.
- On success, retain at least id and accessToken (user id is required for cart and comments) and navigate to Products.
- Do not implement Forgot Password or signup.

Apply specification-freeze accessibility and error-handling rules to the work of this work unit only.

- Meaningful document title and a non-empty meta description. Use semantic landmarks (header / main / nav or equivalent) and a sensible heading hierarchy.
- Do not implement product fetching, search, cards, reviews, comments, add-to-cart API, or cart line items in this work unit.

Apply specification-freeze accessibility and error-handling rules to the work of this work unit only.

Work unit 3 — Product catalog & lazy loading

Implement the Products page listing chrome and lazy-loaded fetching. UX: spec/ux/ux-design-of-product-listing.png and spec/ux/ux-design-of-product-detail.png (listing grid). API: GET https://dummyjson.com/products?limit=10&skip=0 as in spec/apis_contract/ and spec/SPEC_FREEZE.md.

- Heading All Products and a showing-count that updates with loaded items.
- First page: GET https://dummyjson.com/products?limit=10&skip=0. Load more increases skip by 10 (10, then 20, …) until skip + products.length >= total. Do not fetch the complete catalog. Do not use limit=0.
- Handle initial loading, subsequent loading, empty response, products API failure (keep already loaded products on load-more failure), and end-of-list (hide/disable Load more when no more pages).
- A simple list of loaded products is acceptable in this work unit if cards are incomplete. Search field may wait for the search work unit.
- Do not fetch from any substitute catalog API.

Work unit 7 — Add comment

Add comment functionality inside the review modal using POST https://dummyjson.com/comments/add. API: spec/apis_contract/05_Add_Comment.md.

- Send { "body": "<comment text>", "postId": <product id>, "userId": <login id> }.
- Validate non-empty input. Optional 1–5 star rating in the UI; if collected, show it on the local review row (the POST has no rating field).
- Handle loading and POST failure (keep existing reviews and show an error).
- After HTTP success, append the comment to that product's review list in frontend state (the API does not persist).
